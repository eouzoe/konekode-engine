# Konekode 學習引擎

Konekode 貓貓競程的學習系統本身：知識結構、評估學生現在在哪個狀態、掌握與遺忘、能力、下一步做什麼。網站、畫面、美術在另一個倉庫，只透過這裡編出來的 WebAssembly 呼叫引擎。

## 它做什麼

- 從內容（題目、標準解、單元）算出知識結構：語法的構造來自編譯器的語法樹，編輯操作來自編輯規則，題目需要的技能來自哪一份解過哪些子題組。
- 從一份只增不改的事件，算出學生的狀態：會什麼、有多確定、還記得多少、各項能力到哪。
- 回答下一步做什麼、該複習什麼，以及每一個判斷的依據。

## 原則

- 一個學生、沒有任何資料時就要好用；用他自己的紀錄越來越好。
- 純函式、不讀時鐘、可以重播；換裝置重算結果一致。
- 結構是算出來的，不手寫對照表。

## 現在有什麼

- `konekode-space`：學習空間。規則寫成「會了這些就能學這個」，可以有好幾種「這些」；算出哪些是合法的狀態、現在能學什麼（外緣）、剛學會什麼（內緣）、從某個狀態到某一格還差哪些、只看一部分時的樣子（投影）；以及技能與題目的對照（一題可以有好幾組技能）。
- `konekode-assess`：從作答判斷學生在哪個狀態。在合法的狀態上維持機率，每一筆作答照「會了卻答錯」「不會卻答對」兩個機率更新；這兩個機率依作答的條件而不同，示範不算證據；下一題挑答對答錯最難猜的那一題。

從網站搬過來的：

- `konekode-text`：和瀏覽器一致的字串處理（切片、空白、取代、排序）。
- `konekode-complete`：補全的清單與成對符號的規則。
- `konekode-edit`：編輯器的規則，也就是學生每一步能做什麼、做完變成什麼。
- `konekode-unit`：單元的格式，以及每一關的程式與解法路徑。
- `konekode-typing`：打字練習的判斷與鍵盤配置。
- `konekode-run`：執行結果與編譯錯誤怎麼說給學生聽。
- `konekode-record`：事件的格式、讀舊版本、排序與去重。一份紀錄只有一種順序，不管事件照什麼順序到。
- `konekode-learner`：從一份紀錄一趟摺出進度、解鎖，以及每一步的證據（用到哪些知識點、是不是第一次、有沒有被帶著做、隔了多久）。

把它們串起來的：

- `konekode-flow`：資料流。收件時檢查每一批上傳和它的登記是否相符，整理成每台裝置一份紀錄；引擎可以一筆一筆加事件，只有插到中間時才整份重算。
- `konekode-wasm`：給瀏覽器的 WebAssembly 介面。
- `konekode-cli`：同一條資料流的命令列版本（`konekode flow`、`collect`、`state`）。

## 開發

需要 [devenv](https://devenv.sh)。

```sh
devenv shell -- just check
devenv shell -- just wasm
```

`just wasm` 把瀏覽器用的套件建到 `pkg/`。

## 版本與發布

網站只透過有版本的套件用引擎，不抄檔案進去。

- 版本號只有一個來源：`Cargo.toml` 的 `workspace.package.version`。
- 介面不相容（拿掉或改名一個函式、改了參數或回傳的形狀）就升主版本；只增加升次版本；只修行為升修訂版本。`1.0.0` 以前，主版本的角色由次版本擔任。
- 發布：改好版本號、推上 `dev` 並等 CI 過，在那一筆打 `v<版本號>` 的標籤並推上去。`Release` 工作流程會重跑整套檢查，用 `just package` 建出 `konekode-engine-<版本號>.tgz`，附上建置來源證明，掛在同名的 Release 上。標籤和版本號對不上時它會拒絕。
- 用的一方：依賴寫成那個 Release 的檔案網址，鎖檔會記完整性雜湊；`gh attestation verify <檔案> --repo eouzoe/konekode-engine` 驗它是這個倉庫的工作流程建的。
- `just package` 在本機也能跑，同一份原始碼建兩次的檔案位元組相同。
